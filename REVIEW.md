# Код-рев'ю: Verdal store agent

**Дата:** 2026-08-20
**Обсяг:** README.md, DECISIONS.md, SPEC.md, `src/agent/*`, `Makefile`, `data/*`, `eval/*`
**Метод:** усі ключові твердження перевірені запуском реального пайплайна
(`GROQ_API_KEY=""` — tail деградує детерміновано, без мережі), не лише читанням коду.
**Рамки:** архітектура (детермінований роутинг + LLM у хвості) не оскаржується —
вона відповідає обмеженню p95 ≤ 500 мс і обґрунтована в DECISIONS.md. Нижче лише
дефекти реалізації.

## 1. Реальні баги

### 1.1. Мертвий корінь `"достав"` у `compute._shipping_signal` — compute-tier тримається на слові «стандартна»

`src/agent/compute.py:50`

Токени стеммяться до 5 символів (`normalize.py:15`, `STEM_PREFIX_LEN = 5`),
тому «доставка» → `доста`. А `_shipping_signal` перевіряє
`t.startswith("достав")` — 6 символів. Ця умова **не спрацьовує ніколи**.
У `router._has_root` корені обрізаються до 5 символів (`router.py:78`),
тут — ні: розсинхрон між двома реалізаціями тієї самої перевірки.

Перевірено:

```
Q: Термобілизна M плюс доставка — скільки разом?
   intent=COMPUTE_TOTAL confident=True
   -> [fallback_degraded] Вибачте, не можу впевнено відповісти...
```

Це q007 без одного слова «стандартна». Замість `49 + 12 = 61` — деградація.
Роутер каже COMPUTE_TOTAL впевнено, хендлер здається.

### 1.2. Суфікс «L» у назвах товарів парситься як розмір L

`src/agent/normalize.py:133-137`

Токенізатор розбиває `35l` на `35` + `l`; перший цикл `_extract_size` бере `l`
→ confusable → letter `L`. Перевірено з дослівними назвами зі store.json:

```
Q: Hiking Backpack 35L є?
   -> Hiking Backpack 35L у такому варіанті (розмір/колір) немає.   # 15+2 шт у наявності
Q: Insulated Bottle 1L є в наявності?
   -> Insulated Bottle 1L у такому варіанті (розмір/колір) немає.   # 50 шт у наявності
```

Питання з точною англійською назвою товару — найімовірніший формат у файлі
оцінювача — дає впевнено неправильне «немає» для товарів у наявності.

### 1.3. Ввічливе «Не підкажете…» + «розмір» = POLICY_EXCHANGE

`src/agent/router.py:87-89, 156`

`_wrong_size_phrase` — це просто «не» + «розмір» будь-де в реченні. Перевірено:

```
Q: Не підкажете, чи є 43 розмір кросівок?
   -> [policy_exchange] Один безкоштовний обмін розміру...
```

Питання про наявність, відповідь — політика обміну, `confident=True`.
«Не» — одне з найчастіших слів мови; спрацює й на
«не бачу на сайті, чи є розмір M» тощо.

### 1.4. Голе число після назви товару стає розміром

`src/agent/normalize.py:158-165`

```
Q: Хайкінг рюкзак 35 є в наявності?
   size=35 -> ... у такому варіанті (розмір/колір) немає.   # знову 17 шт у наявності
```

«35» — частина назви товару («рюкзак 35 л» — офіційний алiас у facts.json),
але без токена «л» дискваліфікатор не спрацьовує.

### 1.5. Рік / будь-яке ≥4-значне число після слова «замовлення» стає номером замовлення

`src/agent/normalize.py:122-129`

```
Q: Замовлення від 12 серпня 2026 ще не приїхало
   -> Замовлення #2026 не знайдено. Перевірте номер, будь ласка.
```

Гейт роутера (`router.py:124`) робить це `confident=True`, тож у tail питання
не потрапляє.

### 1.6. `make build` падає

`Makefile:19`

`python -m agent.build_aliases` — модуля не існує (файл називається
`build_facts.py`). Перевірено: `No module named agent.build_aliases`.
Додатково: таргет пише в `data/aliases.json`, який ніхто не читає (рантайм
читає `data/facts.json`), а закомічений `data/aliases.json` — порожній файл
0 байтів.

### 1.7. «Жорсткий дедлайн 350 мс» не є дедлайном

`src/agent/fallback.py:85`

`httpx.Timeout(0.35)` — це 0.35 с **на кожну фазу окремо** (connect, write,
read, pool), не на весь виклик. Реальний виклик може легально зайняти ~1 с
(connect 0.3 + upload + TTFB 0.3 + читання тіла). Тобто саме той механізм,
який має гарантувати p95 ≤ 500 мс за побудовою (DECISIONS 3: «budget holds by
construction»), гарантії не дає: успішна tail-відповідь за 700–900 мс пройде
без таймаута. Це єдиний баг безпосередньо проти визначального обмеження задачі.

## 2. Дірки в обробці помилок

### 2.1. Немає try/except навколо `agent.answer()`

`src/agent/cli.py:119`

Один виняток на будь-якому питанні — і весь прогін мертвий, `results.jsonl`
не записується взагалі (запис іде після обох пасів, `cli.py:145`). Пряме
порушення власної конвенції CLAUDE.md («Exceptions on the hot path are caught,
logged and turned into a safe answer») і SPEC DoD п.1 («no exceptions raised»).
Конкретний вектор — 2.2; ще один — рядок без ключа `"q"` у вхідному файлі →
`KeyError` у `cli.py:118`.

### 2.2. `content: null` від Groq → неспійманий `AttributeError`

`src/agent/fallback.py:98`

`response.json()["choices"][0]["message"]["content"].strip()` — ловляться
`KeyError, IndexError, ValueError`, але якщо `content` = `null` (буває при
filtered / нестандартних finish reasons), `None.strip()` кидає
`AttributeError`, який не ловиться. У поєднанні з 2.1 — падіння всього прогону
через одну відповідь провайдера.

### 2.3. `_degraded(reason)`: «reason is for logging only», але логування не існує

`src/agent/fallback.py:45-47`

Причина деградації (таймаут vs 429 vs битий ключ) викидається. У кодовій базі
взагалі немає жодного логера. Конвенція каже «logged… never swallowed
silently» — ковтається мовчки.

### 2.4. Дефолт `0` для порога безкоштовної доставки

`src/agent/compute.py:58-60`

`pf.get("free_shipping_threshold", 0)` → якщо `policy_facts` відсутній чи
перейменований після регенерації, `goods >= 0` завжди істинне: **кожен**
compute відповідатиме «доставка безкоштовна». Мовчазна неправильна відповідь
замість помилки; форма facts.json ніде не валідується при старті.

### 2.5. `None` інтерполюється в текст для клієнта

`src/agent/policy.py:22-44, 114-122`

Промпт build_facts явно каже LLM «If a value is not stated, use null». Якщо
null таки прийде, клієнт отримає «протягом None днів». Захищений лише
`_uk_days`; `days`, `refund`, `hours`, `threshold` — ні.

## 3. Розходження код ↔ документація

### 3.1. Артефакт офлайн-фази: три документи описують те, чого немає

CLAUDE.md («generate `data/aliases.json`. That file is committed»), SPEC
(layout: `src/agent/build_aliases.py`; build order п.5: «commit aliases.json»),
DECISIONS 2 («generates `data/aliases.json`») — насправді модуль
`build_facts.py`, артефакт `data/facts.json`, а закомічений `aliases.json`
порожній. Правий лише README. Makefile написаний під застарілу версію
документів — звідси баг 1.6.

### 3.2. DECISIONS 4: «Chosen: Groq, `llama-3.3-70b-versatile`»

Код використовує `openai/gpt-oss-120b` (`fallback.py:27`, `build_facts.py:27`,
підтверджено `_generated_by` у facts.json). Задокументоване рішення називає
модель, якої в коді немає.

### 3.3. DECISIONS 3 / SPEC / README: «hard deadline 350 ms»

Див. 1.7: реалізація не забезпечує заявлену семантику wall-clock дедлайна.

### 3.4. CLAUDE.md, tier 2: «Computed… line totals»

Чистих line totals не існує: «Скільки коштуватимуть два светри з мериносу
разом?» → COMPUTE_TOTAL → `compute_incomplete` → tail → деградація
(перевірено). Хендлер вміє лише goods+shipping і поріг безкоштовної доставки.

### 3.5. CLAUDE.md: «No linear scans over lists on the hot path»

`_exact_match` (`resolve.py:112-117`) — O(N) прохід з `re.search` по всіх ~290
алiас-фразах на кожне питання; `_fuzzy_match` перебудовує список кандидатів на
кожен виклик (`resolve.py:133`). Швидко на цьому обсязі, але це буквально
заборонений конвенцією патерн.

### 3.6. Коментар бреше

`src/agent/compute.py:63-65`: «The router may hand us product=None (e.g.
q037). Try to resolve now» — повторний `resolve()` викликається з тими самими
аргументами і детерміновано повертає той самий `None`. Мертвий код.

### 3.7. Дрібне: README «Measured p95 is 208 ms»

`_pct` (`timing.py:22`) використовує `round((n-1)·q)`: на 39 зразках бере
індекс 36 замість стандартного nearest-rank 37 (перевірено). Самозвітований
p95 оптимістичніший до одного зразка; оцінювач, що перерахує з `ms` у
results.jsonl стандартним методом, отримає інше число.

## 4. Що зламається на файлі питань з іншими формулюваннями

Усе нижче — впевнено неправильні відповіді (не деградації), перевірені
запуском, якщо не вказано інше:

- **Ціна в непрямому відмінку / «вартість».**
  `PRICE_ROOTS = ("ціна", "кошт", "почім", "скіль")`: «ціну/ціни» не проходять
  `startswith("ціна")`, «вартість/вартує» відсутні.
  «Підкажіть ціну куртки Alpine Shell Jacket» → `product_stock_overall`,
  список наявності замість ціни.
- **Порівняння.** Потрібні одночасно корінь із `("дешевш","кращ","порівн")`
  **і** сполучник «чи/або». «Що **дорожче**: рюкзак 35 л чи софтшел-куртка?» →
  впевнена відповідь про наявність одного рюкзака. «Порівняйте X **і** Y» —
  теж повз. q017 проходить лише тому, що там буквально «дешевше… чи».
- **ORDER_ITEMS / ORDER_ADDRESS тримаються на одному корені кожен.**
  «**Які товари** в замовленні #1009?» → відповідь про статус
  (`order_status`), не про склад. Те саме для адреси без «адрес/куди».
- **Не-ЄС визначається переліком {британ, кордон, поза}.**
  «Чи доставляєте ви в **Україну**?» → впевнене «Стандартна доставка по ЄС:
  3-5 днів, 12 EUR…» замість «не доставляємо за межі ЄС». Для україномовної
  аудиторії це питання у файлі оцінювача майже гарантоване — найдорожчий кейс
  цього розділу.
- **Каскад від 1.1:** будь-яке compute-формулювання без буквального
  «стандартна» або «експрес» деградує.
- **Таблиця гомогліфів вміє тільки «М».** Кирилична С → латинська C (не S),
  Л не мапиться взагалі, тому «ХЛ» → не XL. «Софтшелл, розмір **ХЛ** — є?» →
  мовчки ігнорує розмір і перелічує S, L як «у наявності» (перевірено).
  Коментар у `normalize.py:29-32` обіцяє S/M/L/XL — фактично працює лише M.
- **Колір «син» ловить «синтет-».** `COLOUR_ROOTS` матчиться `startswith` по
  сирих токенах: «куртка з **синтетичним** утеплювачем» отримає фільтр
  colour=navy.
- **Будь-яка згадка знижки → REFUSE.** «Чи бувають у вас знижки?» (легітимне
  питання про політику) отримає відмову з формулюванням, ніби клієнт вимагав
  персональну знижку.
- **Масштаб tail на великому файлі.** Прогрівальний пас (`cli.py:140`)
  виконує повний пайплайн включно з живими Groq-викликами — трафік tail
  подвоюється ще до вимірюваного паса. При 30 RPM / 8000 TPM (DECISIONS 7)
  на більшому файлі tail масово ловить 429 і деградує; латентність тримається,
  але якість хвоста колапсує. А кожен *успішний* tail-виклик через 1.7 може
  коштувати ~1 с — p95 тримається, лише поки хвіст < ~5% питань, що вужче за
  заявлені в DECISIONS 3 «15%».

### Другий прохід: залишкові знахідки

Виявлені під час виправлень, поза початковим списком:

| Знахідка | Виправлення | Верифікація |
